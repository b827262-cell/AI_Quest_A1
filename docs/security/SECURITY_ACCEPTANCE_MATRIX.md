## Fixture/environment requirements summary for Codex

1. **Two-learner fixture** (AC-4): seed two distinct learner identities with notes/chat-sessions/progress under the same book, in an isolated test DB — no real learner data.
2. **Class A / Class B fixture** (AC-5): two classes, one teacher each, one shared TA, one draft per class.
3. **Two-workspace fixture** (AC-9): two `orgId`/`scopeId` pairs with distinct `ownerId`, one with a `sharedWithIds` entry to test the *positive* (allowed) sharing path too, not just the negative case.
4. **Adversarial-but-safe PDF corpus** (AC-8): 3–5 small, deliberately malformed/deep/embedded-script PDFs, checked into a test-fixtures directory clearly marked non-executable/test-only, never fetched from a live URL.
5. **Oversized-upload fixture** (AC-11): a generated (not committed) large temp file for the size-limit test — generate at test time, do not commit a large binary to the repo.
6. **Extended SSRF matrix** (AC-12): reuse the existing 15-URL matrix, parameterize it to also run against `credential.baseUrl`.
7. **Deterministic fixture AI provider** (AC-7): a mock provider implementation that echoes/records whether an injected instruction changed its "grading" behavior, so the test is deterministic and never calls a live model.
