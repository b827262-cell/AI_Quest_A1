## The two blockers this build closes (Owner 19:22, taken from my own self-audit)

### ① Google handoff left the student page in the same tab

`88e28ca` fixed the *subject-consent* path, but the failure paths still bypassed consent:

* an `INVALID` verdict and a thrown local error called `handOffToGoogle()`, which sniffed
  `navigator.userActivation?.isActive` and then ran `window.location.assign(url)` — the
  learner's page was replaced by Google without ever being asked;
* the stalled-download escape hatch was a bare `<a href=…>` with no `target`, i.e. the same
  same-tab navigation;
* neither path had the per-question consent the Owner contract requires.

`b67f28e` routes **every** handoff through one funnel:

| Step | Behaviour |
| --- | --- |
| local attempt fails (`INVALID` / `timeout` / `local-error`) | `requestFailureHandoff()` calls `guard.done()` first, so the local attempt is terminated and cannot later navigate; sets a learner-facing error and opens the consent dialog |
| consent dialog | new `consentKind: "subject" \| "failure"` state + `consentReason` from `handoffReasonLabel()`; each dialog mints its **own** `createAutoFallbackGuard()` into `consentGuardRef`, so the one-shot budget is per dialog |
| 「同意並在新分頁開啟」 | `openConsentHandoffTab()` → exactly one `window.open(url, "_blank")`, opener severed, no features argument (a `noopener` third argument makes `window.open` return `null` on success and would double-fire the fallback) |
| popup blocked | visible manual `target="_blank" rel="noopener noreferrer"` link — never a navigation |
| stalled download | the Google link is now `target="_blank" rel="noopener noreferrer"` with 「（新分頁）」 in the label |
| cancelled download (`/已取消/`) | unchanged: `guard.cancel()` + error only, **no** dialog, **no** navigation |

Removed outright: `window.location.assign`, `document.location`, `window.location =`, and the
`navigator.userActivation` sniffing. `site/tests/auto-fallback.test.mjs` now pins that with a
`page.tsx` **source gate** (regex over the whole file, plus the INVALID/timeout branch
routing, the `guard.done()` + `requestConsentedHandoff(originalQuestion, "failure"` pair, the
per-dialog guard, the `原因：{consentReason}` line, and the fact that subject-only shortcut
buttons are hidden in `failure` mode).

`site/scripts/run-chrome-e2e-suite.mjs` Case 3 was rewritten from 「hands off to Google exactly
once (same-tab)」 to 「asks consent and hands off to ONE new tab」: it polls for
`.v2-subject-consent`, treats a dead page context as a **FAIL** (that is how a same-tab
regression would show up), asserts `dialog.nav === 0`, that the origin tab is still on `SITE`
after the click, and diffs `/json/list` before/after to require **exactly one** new
`https://www.google.com/` page target. `node --check` passes; **the suite was not executed in
this run — it belongs to AGY after the Codex same-SHA review.**

### ② Simplified residue passed through and was reported VALID

`site/app/hant-set.ts` is auto-generated (`fixtures/gen-hant-set.py`; **not** hand-edited here)
and classifies a character as `ambiguous` whenever *any* Big5-legal traditional homograph
exists. Ambiguous chars are then neither rewritten nor flagged — 123 characters of hole. A
model answer containing 计算**机**, 并, 优, 据, 极, 构, 种, 触 … sailed through `normalizeToHant`
and `hasUnresolvedSimplified` returned `false`, so the lane stamped it **VALID**.

Fix is layered *on top of* the generated table, so regenerating `hant-set.ts` cannot undo it:

1. **`RESIDUE_CHAR_MAP`** — 21 curated character overrides, consulted before `HANT_MAP`:
   `机 并 优 怀 据 极 构 洁 种 胜 触 圣 坏 惊 气 虫 适 价 异 着 愿`.
   Their keys are folded into `SIMPLIFIED_SET`, so detection fails closed if one ever survives
   conversion. Exported read-only as `RESIDUE_OVERRIDE_CHARS` for the invariant test.
2. **`CORE_PHRASES`** — 139 word-level entries now (was 22; **+117**), applied before character
   conversion and able to carve a protected span. Grouped by the ambiguous character they
   disambiguate: 于 (于是/由于/位于/属于/关于/对于/用于/处于/低于/高于/等于/至于/易于/善于/便于/
   鉴于→鑑於/归于→歸於/着眼于→著眼於 …), 范 (范围/规范/示范/范畴/防范/模范 …), 后 (以后/然后/最后/
   之后/随后/事后/背后/后来/后者/后天/午后 …), 余, 里 (那里/哪里/里面/心里/手里/家里/夜里), 几,
   复 (恢复/复杂/重复/反复/复制/复兴/复数/复习 …), 准 (标准/准则/准时/水准/瞄准), 采 (采用/采取/采购/
   采访/采集/开采/采纳 …), 征 (特征/象征/征兆), 伙, and **划: 计划→計畫, 企划→企劃, 策划→策劃,
   筹划→籌劃, 划分→劃分, 划拨→劃撥**.
3. **Surname-position rule** — `于`/`范` are surname-bearing, so they are never blanket-mapped.
   `CONTEXTUAL_RESIDUE` + `isSurnamePosition(chars, i)` (non-CJK neighbour, string start, or a
   `SURNAME_INTRODUCERS` token behind it — 是/姓/教授/先生/書法家/院士 …) decides whether a bare
   `于`/`范` counts as residue. `阿里山位于…` → `阿里山位於…`; `于右任` and `范仲淹` stay as-is.

**「計划」 review the Owner asked for.** `划` is Big5-legal (「划算」 must stay 「划算」), so the
residue cannot be fixed at character level; it is fixed per word. Taiwan official usage is
計畫/企劃 (same precedence rule that already maps 数据 → 資料), so 「計划明年上線」 was a
mixed-form word being served as VALID. Now: 「计划明年上线。」 → **「計畫明年上線。」**, pinned by the
rewritten Gate-B tradeoff test.
