## Reproducibility: NOT reproducible (measured 2026-09-24)

Three clean `rm -rf dist && npm run build` runs from the same committed tree
(`a5e1de6`, whose `site/` is byte-identical to `af22d5a` — the only delta is files
under `docs/`) produced three different package digests:

| --- | --- | --- | --- | --- |
| 1 | `74a4d46b0e2c…` | 99 | 2,712,148 | `transformers-CDNiJW7e.js` |
| 2 | `ee1022bbb43d…` | 99 | 2,712,148 | `transformers-BczFLBf5.js` |
| 3 | `dea3892252a1…` | 99 | 2,712,148 | `transformers-Din_zi3a.js` |
| 4 | `bcf58cd69c64…` | 99 | 2,712,148 | `transformers-DAvJ_kTU.js` |

Comparing build 2 against this record's manifest: 99 vs 99 files, **47 rows
differ**, and every file that survives under the same name has an *identical byte
length*. The differences are hashed chunk filenames (`transformers-*`, `index-*`,
`page-*`, `prompt-api-polyfill-*`, …) plus every stable-named file that embeds
those names (`server/index.js`, `server/.vite/manifest.json`,
`client/.vite/manifest.json`, `server/__vite_rsc_assets_manifest.js`).

Full digests, in build order:

```

ee1022bbb43d1f83f5977e7eab43336125352e73836208f9a3228c4420faadf0  (build 2)

```

**Root cause.** Vite/Rollup (via `vinext`) assigns content-hash chunk names from
per-build module id / ordering state that is not fixed across invocations, so the
emitted names rotate even when the bundled source does not. Because chunk names
are referenced from other chunks and manifests, the rotation propagates through
most of the package while total size stays constant. `dist/` embeds no git SHA, so
this is not provenance-keyed output — it is build nondeterminism.

**Consequences for gating.**
* `PACKAGE_SHA` identifies *a* build; it cannot verify *the* build from a source
  SHA. Any gate that compares a recorded `PACKAGE_SHA` after a rebuild will fail
  spuriously, and any that only checks "a digest was recorded" proves nothing
  about which source produced it.
* `FILE_SIZE_GATE` is unaffected — it is a per-file size bound, and it PASSed on
  every one of these builds.
* What still holds: the manifest beside this file is an authentic snapshot of the
  bytes of build instance 1, so those exact bytes can be re-hashed if the archive
  itself is retained. Linking source→bytes therefore needs the built artifact
  archived, or a deterministic-build fix upstream.
