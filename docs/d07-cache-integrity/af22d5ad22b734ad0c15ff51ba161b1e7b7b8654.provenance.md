## Reproducibility: NOT reproducible

Five `rm -rf dist && build` runs against byte-identical `site/` produced five
different package digests. Two have retained evidence:

| `PACKAGE_SHA` | retained evidence |
| --- | --- |
| `74a4d46b0e2c4e180ddd39b29a95722c8e082b626acc7e338ab3adfbb4d80ca5` | manifest only (`e0e3f7e9…`); bytes discarded |
| `8fd53757d418ec0e89249a01b00999786e1d271cd7c84b0dbf72dabad5570c28` | **archive `499fc11e…` — re-hashed, reproducible** |

Three intermediate builds (`ee1022bbb43d…`, `dea3892252a1…`, `bcf58cd69c64…`) were
observed and their `PACKAGE_SHA` values noted, but their bytes and manifests were
discarded, so those three are not independently re-verifiable. Two confirmed
distinct digests from identical source are sufficient to establish the finding.

Between the two evidenced builds, comparing the retained manifests: 99 vs 99
files, same 2,712,148 total bytes, **47 rows differ**. Every file that survives
under the same name keeps an identical byte length; what rotates is hashed chunk
names, e.g.

```
build 74a4d46b  client/_next/static/chunks/transformers-BczFLBf5.js   549,044 B
build 8fd53757  client/_next/static/chunks/transformers-N-gn7TSg.js   549,044 B   # same size, new name
both builds     server/ssr/_next/static/transformers-C9udp9y0.js      548,935 B   # byte-identical (fa72a1d0…)
```

and the rotation then propagates into every stable-named file that references
those names (`server/index.js`, `server/.vite/manifest.json`,
`client/.vite/manifest.json`, `server/__vite_rsc_assets_manifest.js`).

**Root cause.** Vite/Rollup (via `vinext`) assigns content-hash chunk names from
per-build module id / ordering state that is not fixed across invocations. `dist/`
embeds no git SHA, so this is build nondeterminism, not provenance-keyed output.
Per the Owner's instruction this lane does **not** change build tooling and does
not attempt a deterministic-Vite fix; freezing one instance is the sanctioned
workaround.

**Consequences for gating.**
* `PACKAGE_SHA` identifies *a* build. It cannot be recomputed from a source SHA,
  so no gate may treat "rebuild and match" as a check, and no reviewer should
  expect a fresh `npm run build` to reproduce `8fd53757…`.
* Binding source→bytes requires these archive bytes. Same-SHA Gate-D, Hermes
  zh-Hant review and AGY Chrome E2E should run against the extracted tree (or the
  served equivalent), not a new build.
* `FILE_SIZE_GATE` is independent of the rotation — per-file bound, PASS on every
  build above.
